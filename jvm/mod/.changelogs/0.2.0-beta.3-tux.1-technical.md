# 0.2.0-beta.3-tux.1: under the hood

The first fork release, cut from the joined repository: the website at the root, the mod in `jvm/mod`, and plain-Java
core modules in `jvm/core` that both use. Base version 0.2.0-beta.3; tag `mod-0.2.0-beta.3-tux.1`.

## What the mod now takes from the core

The jar shades ten core modules, each compiled once for the mod and once for the website:

- `core-base`: ids, the number formatter, exact maths (fdlibm), ordered hash maps, the log, settings and text seams.
- `core-solver` and `core-ojalgo`: the balancer and its LP engine. Answers are bit-identical on every JVM and in the
  browser across the 107-plan corpus; they no longer depend on the player's Java version.
- `core-machines`, `core-power`: machine and power maths, with the pack's rates (GTNHRates read live when present).
- `core-model`, `core-plan-solve`: the plan model (nodes, drawers, groups, wires, resources, recipe references) and the
  plan-to-solver step. One GregTech recipe reader (`GtRecipeRecord`) serves the dataset export and the mod.
- `core-codec`: plan JSON, plan codes and the save codec, with no reflective binding. A world saved by beta.3 opens
  as it was (below).
- `core-layout`: the wire router and Arrange, translated line for line from the website's.
- `core-view`: card, Overview, notices, drawers, groups, notes and minimap as view records the game draws.

Packaging: every core class is in the jar, at Java 8 bytecode at the root, with the original release-21 class under
`META-INF/versions/21/` where the downgrader changed it; the mod's own classes keep their Java 25 originals under
`META-INF/versions/25/`. Java 8, Java 17 to 24 and Java 25 each load a different mix, and all three were run.

## For the server operator

The jar names no remote host. Everything it may contact comes from the `network` category of
`config/gtnhplanner.cfg`, and every key is empty in a fresh install. Empty switches the feature off and nothing is
contacted: the Library's Community tab, Sign in and Post say "No community site is set up on this install.",
Feedback says sending is not set up, the update check does not run and Open in the mod does not listen.

A fresh jar writes this block:

```
network {
    S:liveUrl=
    S:siteUrl=
    S:supportUrl=
    S:updateUrl=
    S:websiteOrigins <
     >
}
```

- `siteUrl`: the website, `http://` or `https://` and a host. Turns on the community library, accounts and posting,
  bug reports, cloud plans and plan links.
- `liveUrl`: the live service, `ws://` or `wss://` ending in `/live`. Empty derives it from `siteUrl`.
- `updateUrl`: an address answering with a release list in GitHub's releases JSON. Tags may be `mod-<version>` or
  `<version>`; `-tux.N` orders after its base version and before the next one; anything else (`web-*` tags) is skipped.
  Empty: no update check.
- `supportUrl`: a help page the Feedback box links to. Empty hides the link.
- `websiteOrigins`: one origin a line, besides the site's own, allowed to send plans with Open in the mod. With
  `siteUrl` or an origin set, the game listens on the first free port of 127.0.0.1:25640 to 25649.

The system properties `-Dgtnhplanner.library.url`, `-Dgtnhplanner.live.url`, `-Dgtnhplanner.update.url` and
`-Dgtnhplanner.support.url` win over the file. A saved sign-in belongs to the site that issued it and is never sent to
another.

The mod works on the client. On a dedicated server it loads, writes its config and does nothing else; installing it
there is optional. If it is installed there, give the server the same jar as the clients.

## Checked in a game

- Dev client (GregTech set, Java 25): cards from NEI's Smelting, Shaped Crafting and Bending Machine pages, a wire, a
  product drawer at 1/s: 10 furnaces and 2.8 LV benders, the same as the website's solve of the exported file.
  Arrange, a world reload (board identical), a website plan imported and exported (every wire resolves, every machine
  count equal to the website's own solve).
- No site set: the Community tab, Sign in, Post, Feedback and the update check behave as above, and a logging proxy
  plus a socket sampler saw no connection from the planner.
- A local stand-in site set through the config file: account creation, sign-in, the Community list, a post, cloud
  plans up and down (sign out and in again gives the same board), the live room with a second person, and the update
  offer.
- The operator's 2.9.0 client pack with no network, Java 21: a world saved by 0.2.0-beta.3 opens with every card,
  count, port rate, drawer and wire as it was (wire paths are the new router's); NEI's plan button adds a card.
- Java 8 dev client: starts, imports and solves the same plan to the same counts.
- Dedicated dev server with GregTech: starts with the jar, and a client with the jar joins it and plans.

## Known differences

- Wire paths in a beta.3 save are routed again by the new router; which ports each wire joins does not change.
- A website drawer that is both fed and drawn from, with its surplus sent out as a product, comes into the mod as a
  plain buffer and goes back out without that surplus setting.

# 0.2.0-beta.3-tux.3: under the hood

The third fork release. Base version 0.2.0-beta.3; tag `mod-0.2.0-beta.3-tux.3`. The same jar goes on the server and
on every client.

## What changed

- Card menu: `RecipeCard` shows the shared rows from core-view `CardViews.menu`. Add another recipe appears unless
  the card owns its recipe (`BoardSession.ownsRecipe`: generators, holders, crop cards, crop farms, EEC). Replace the
  recipe appears unless the card is shared, a holder or an empty crop farm. Both arm NEI's + for the card
  (`BoardSession.armRecipePick`). The pick joins the card (`CardRecipes.join`, refused when no machine runs every
  section) or replaces it in place (`CardRecipes.replace`: id, place, group, count rule kept, wires follow by
  resource). Each is one undo step. The board's return disarms an unused pick.
- Number pad: `KeyText.typed` reads a pad key that arrives with no character as the character it prints. A real
  character wins, so a key with both types once. Used by `InlineNumber`, `TextArea`, `NoteCard`, `PasswordField`,
  and the ModularUI fields of `NumberPopup` and `TextPopup` (`KeyText.forField`).
- Plan files: `FfImport` reads `settingPins` through the same `PlanPins` reader as cloud plans, keyed by
  `pinName` (the website's handler id, `power:<source>`). File, paste, Open in the mod and library downloads all
  show them. An empty custom rate card and an empty fluid tank come back as themselves (`FfCards.emptyCustomRate`,
  the empty tank).
- Sign-in redirect: Create one says accounts are made on the website. Dialog errors wrap to two lines.
- Crop cards hand the solver their exact harvest time in ticks (fractional), as core and website do.
- Core, shared with the website: every number a solve hands out is cleaned once where it leaves the solver
  (core-base `SolvedNumber`: a value within 1e-12 of a small fraction becomes that fraction). Coil discounts of the
  Industrial Coke Oven, Mega Oil Cracker, Mega Alloy Blast Smelter, Large Fluid Extractor and Large Thermal Refinery
  use the game's repeated squaring (`powInt`).

## For the server operator

No config key, JVM argument or pack dependency changed since tux.2. The `network` block and its rules are as the
tux.2 technical notes describe. A fresh install still names no site.

## Checked in a game

Dev client (GregTech set, Java 25), no site set unless said:

- Menus: a GT card shows Clone, Add another recipe, Replace the recipe, Add to a task, Delete. A generator shows no
  Add another recipe. An empty crop farm shows neither row.
- Add another recipe on a Bending Machine: NEI opened on the machine's list, + joined the recipe as a second section
  (exported as a shared machine), the toolbar undo took it back in one step. Replace from the Iron Plate page put a
  crafting card in the same place under the same id; undo took it back. Escape on the armed NEI page, then + on
  another page: a new card.
- Number pad events with no character: a count box took 1, 2 and a 3 sent with its character as 123. The number
  popup (a rate chip) typed nothing from the pad before `KeyText.forField`; that fix is covered by `KeyTextTest`.
- A plan file with a generator reading pin and a machine pin: the reading shows on the generator's strip, and both
  pins go back out unchanged. An empty fluid tank and a custom rate card came back as themselves at their rate.

Real 2.9.0 pack, networking off: a save made under tux.2 with a website plan of view-only cards and drawers, a
website plan with two shared machines, and a crop card opened under this jar with the same cards, places, counts,
drawers and wires. Opening it did not rewrite the save. The exports differ only where a solved count lost float
noise (0.125000000000001 became 0.125).
